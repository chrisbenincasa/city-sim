# Verification and limits

Research-only bundle. No tracked game files, Rulesets, ADRs or corpus checks were edited. The first-pass research remains intact. No commit, Godot run, gameplay test, production asset or external publication was made.

Reproduction commands, from the repository root:

```sh
python3 research/city-architecture/output/02-present-day/build_bundle.py
python3 research/city-architecture/output/02-present-day/validate.py
```

The validator checks the seven required outputs, source-ID consistency, original-unit/metric arithmetic, unique measurement keys, local HTML/Markdown links, SVG structure and text anchors, the 52-ID archived sample, N3 circulation arithmetic, and byte-stable regeneration. It executes the actual blend JavaScript in a Node DOM harness across all 101 integer settings and the three preset buttons, checking endpoints, midpoint, stable slot types and monotonic selection. This is script behaviour verification, not browser automation.

Visual inspection is sampled. Quick Look rendered the scale sheet and opening portions of both HTML artifacts. Quick Look disables JavaScript; the blend therefore includes a pre-rendered static midpoint as well as its interactive behaviour. The full long atlas was not visually reviewed in a browser. Source-plan inspection and access failures are recorded in the internal evidence log and sources table. Local links were checked; this is not an automated live-HTTP link audit.

The original-unit conversions preserve arithmetic precision, not measurement accuracy. Published proposals are explicitly distinguished from built-project reports, energy-typology examples, manufacturer calculations and authored game-model parameters. Unknown envelope dimensions and roof details remain gaps. No source image was measured in perspective, no occupancy was inferred from windows, and no generated raster image was used as evidence.

Research source downloads and QA thumbnails remain in temporary storage. The bundle uses original analytical diagrams and links to third-party imagery; it does not redistribute the downloaded PDFs or photographs. TABULA attribution is visible in the atlas and table.

Remaining prototype verification: in-engine silhouette and access legibility; regional preference and street coherence in motion; day/night/material/condition/overlay comparison; performance. These require the follow-on Godot prototype, the drive skill and a Debug build. This research does not claim those checks passed.

Final result: PASS — seven required outputs, 22 source IDs, 122 dimension/conversion rows, claim-source references, local links, SVG structure, 52 archived Building IDs, static midpoint, blend script checks and byte-stable regeneration. Closing scale-sheet content and the corrected static blend were also previewed; the visual-review limits above still apply.
