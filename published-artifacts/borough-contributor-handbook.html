Your first hour

Three commands. All of them work today, on a machine with no GPU and no Godot installed.

dotnet build      # 4 projects + tests + 2 spikes. ~3s. Warnings are errors.
dotnet test       # 1,050 test methods
dotnet run --project src/Borough.Headless

That last one builds a 10,000‑Citizen city and prints its tables and a State Hash. This is the real output:

The one sentence that explains the whole design

A million people need to get to work, a Tick is 15.6 ms, and a path search per journey costs more than the entire budget — so nobody searches. A driver remembers a route, glances one junction ahead, and is stubborn about changing its mind. Almost every mechanism in this codebase is a consequence of not being able to afford the obvious thing.

The boundary rule, and how it is enforced

Core returns ids and numbers, never human‑readable strings. The shell owns every string a human reads, resolved through the Ruleset. The real leak vector is not using Godot; — it is a method that returns a formatted string because a panel wanted one. tests/Borough.Tests/BoundaryTests.cs asserts all three by reflection: no Godot reference, no floating‑point state, no human‑readable strings.

Toolchain

  • .NET 10.0.x, pinned by global.json with rollForward: latestFeature — accepts 10.x, refuses 11.0.
  • Directory.Build.props applies to every project: net10.0, Nullable=enable, TreatWarningsAsErrors=true, Deterministic=true, and InvariantGlobalization=true — culture must never reach a number or a parse.
  • The solution file is Borough.slnx (XML format), not .sln.
  • .editorconfig at the root is not optional. Warnings‑as‑errors plus the recommended analysers turns CA1707 (underscores in member names) into a build error, and every test name in this repo is a sentence with underscores.

The non‑negotiables, and the compiler errors that enforce them

These rules fail silently when broken — a divergence appears three hundred Ticks later on somebody else's machine. So they are compiler errors, not conventions. Every diagnostic has a test that writes the violation and watches it fire; do not add one without.

The arithmetic substrate

Borough.Core.Arithmetic is the one namespace exempt from BOR0203/BOR0204, because it is where their replacements are implemented. The match is on the exact namespace, not a prefix — a child namespace does not inherit the exemption. There is no Math.* anywhere, including there.

  • IntegerMath — FloorDiv is the default rounding. C# truncates toward zero, which is deterministic but is a directional bias that flips sign at every zero crossing.
  • Fixed — Q16.16 is a raw int plus a static helper class, not a struct. One = 65536. This is the only place checked appears in Core, and it always wraps an expression rather than a block.
  • Transcendental — 256‑entry committed tables plus linear interpolation for Exp/Log. The tables are hash‑bearing world constants.

Quantities carry their units

Every quantity is a readonly record struct X(TRaw Raw) with hand‑written operators. The discipline: a quantity multiplies by an int count or by a Ratio, never by its own kind. Conversions from human units (km/h, seconds, minutes) happen at Ruleset load, never per‑Tick.

TypeBackingScale
Ticksulongwhole Ticks. PerDay = 2048; one Tick is 42.1875 s of in‑world time
Tilesintwhole Tiles; Metres = 4
SubTilesQ16.16Tiles — positions only
SpeedQ16.16Tiles per Tick
TravelTimeQ16.16Ticks. Impassable is a sentinel, and + saturates
Moneylongsmallest unit; signed on purpose
RatioQ16.16dimensionless — the only type where fixed × fixed is legal

Two bugs this discipline caught, both of which would have shipped silently

TravelTime.operator+ was prose with no implementation, and the bare int addition wrapped Impassable + 1 to a large negative cost — which a shortest‑path search would then have preferred over every real route. And Speed.PerKilometrePerHour was a hardcoded literal 48_000; when the clock changed, an authored walk_speed_kph = 5 would have walked the city at 1.25 km/h with nothing failing to compile. It is now derived from Ticks.PerDay and Tiles.Metres.

Randomness is a function, not a stream

public static ulong Draw(WorldKey world, ulong entityId, Ticks tick, PurposeTag purpose)

Three SplitMix64 rounds, one per varying coordinate. Because it is counter‑based, a draw does not depend on how many draws preceded it — which is what lets the Decide phase be parallelised later with bit‑identical results. Save the seed, never the key; WorldKey.FromSeed is the only constructor.

Adding a PurposeTag

Append at the end of the enum with an explicit value one higher. Never renumber, never slot one beside a sibling — the value is a hash input, so renumbering invalidates every Input Log and hash baseline. Add it only when the mechanism that draws under it is being built. Write the doc comment saying which other tag it is distinct from and what correlation sharing would create — every existing member does this. Values 0–15 are in use today.

The failure that enum exists for is recorded in its own source: a spike drew one hash and pre‑shifted it for two coordinates, the reduction ate the top bits, and every Arterial took the same heading — while the footprint table looked healthy throughout.

03

Typed tables and the State Hash

There is no ECS (rejected explicitly — the population is homogeneous, and ECS earns its complexity through heterogeneous composition) and no object graph. Storage is structure‑of‑arrays: a hand‑written class marked [Table] that holds a Rows<T>. The tag T is an empty struct whose only job is to type Handle<T>, so a Citizen handle cannot index the Building table.

[Table]
public sealed class BuildingTable
{
    private readonly Rows<Building> _rows;

    public BuildingTable(int capacity, LotTable lots)
    {
        _rows = new Rows<Building>("building", capacity, Buffering.OneCopy);

        Lot          = _rows.SavedHandle("lot", lots.Rows);   // HandleColumn<Lot>
        Kind         = _rows.Saved<byte>("kind");             // Column<byte>
        OccupantHead = _rows.Derived<int>("occupant_head");   // rebuilt, never hashed
        BinHead      = _rows.Derived<int>("bin_head", Touch.PerTick);

        _rows.Seal();
    }
    ...
}
The mechanism worth internalising

Declaring a column is what allocates its storage. There is no way to get an array without stating a Disposition, so the State Hash cannot have a coverage hole. Disposition is one enum — Saved (written to the save and folded into the hash, both, by construction) or Derived (neither, rebuilt from saved state) — rather than two booleans, precisely to make "saved but not hashed" unrepresentable.

How the hash is composed

Handles, slots and ids

A Handle<T> is {index, generation}. Generation is even = free, odd = live, and 0 is reserved for the unset handle, so parity survives a 231 wrap. The table has a free list and never compacts — relocation would be undetectable by the generation counter. There is deliberately no unchecked fast path on Resolve: a dangling read in a deterministic sim is a divergence, not a crash.

Handle<T> is not IComparable and has no relational operators, because ordering by a handle index is a determinism bug — indices recycle.

Intrusive index lists

Every variable‑length collection in Core is one of these: a head/tail on the owner, a next on the element, all in flat arrays. Never a per‑entity collection object — measured at 6.98 ms against 100.20 ms at the 1M target, which is what makes BOR0701 an error rather than advice.

Two details that will bite you

The stored value is slot index + 1, so 0 means empty. Zero‑filled and freed rows would otherwise read as "owns slot 0".

A Derived list must use InsertOrdered; a Saved list whose order carries meaning uses Append. A rebuild only has slot order available, so a derived list built with Append reproduces plausibly rather than exactly, and the hash notices.

04

The Tick

The whole simulation is one method. It is written out straight rather than table‑driven, because the phase ordering is the determinism contract.

public void Step(in TickInput input)
{
    Ticks tick = _world.Tick;

    Reload(input, tick);        // inside phase 0
    ApplyInput(input, tick);    // 0  Input
    Wake(tick);                 // 1  Wake
    Decide(tick);               // 2  Decide
    Settle(tick);               // 3  Settle
    Move(tick);                 // 4  Move
    Layers(tick);               // 5  Layers
    Growth(tick);               // 6  Growth
    Commit(tick);               // 7  Commit

    _world.Advance();
}
Correction to CLAUDE.md and the board

Both say "two of the eight Tick phases are still empty" and that nothing in the Tick calls the Movement tables. Neither is true any more. All eight phases call at least one engine; phase 4 has run CommuteEngine then TripEngine since milestone 5b. The nearest thing to a stub is phase 7, which does only the staggered invariant slice.

The Decide guard

Simulation.VerifyDecideWritesNothing defaults to on. It folds every column of every table — including derived ones — before and after phase 2, and throws on a mismatch. It is O(world) twice per Tick, so long runs at scale need --no-decide-guard. Leave it on for everything else; it is the check that keeps the propose/apply split honest.

Commands, and the Input Log

A Command is 12 bytes with no padding: Kind, a payload word, and two Tiles. Payloads pack into that single word so the log format stays at version 1 — a sixth field would bump the codec version and cost every log ever written.

CommandKindStatus
None = 0reserved, never valid
Zone = 1zones the block the named Tile falls in; the subdivider carves it
Connect = 2one Street Segment, laid or bulldozed. Arterials refused by name
Service = 3declared, not applied — throws
Govern = 4declared, not applied — throws
Populate = 5synthetic city. An instrument verb, expected to be deleted
Trip = 6a test affordance rather than the only door. Also expected to be deleted

What guarantees replay: a replay starts from an empty world — there is no initial‑state file, so every difference between two cities is a difference in their logs. Randomness is counter‑based. And Apply throws on any verb it does not apply, so a log can never run "successfully" while diverging.

Invariants

Three tiers, sorted by frequency and never gated on build configuration — the runs that surface these bugs are release‑build, million‑Tick balance runs.

  1. PerTick — O(1), at the write site. A mutation asserting about itself. Not in a registry.
  2. Staggered — one slice of rows per Tick; the whole world covered every 64 Ticks.
  3. EndOfRun — expensive whole‑world walks, once per run however long.

To add one: append to enum Invariant with the next unused number (0–39 today), write the check in WorldInvariants.cs, and register it. Ids are retired, never reused — HouseholdHomeExists = 3 is [Obsolete] and kept, because that number travels in crash artifacts written before the change.

05

Rules and Rulesets

No tuning number is a const in simulation source. Everything a designer would want to change lives in a TOML Ruleset and is hot‑reloadable. A const where a Ruleset value belongs is a defect, not a shortcut.

Two Rule families, and what actually distinguishes them

They differ in when an effect becomes visible within a Tick — which is observable behaviour, so moving a mechanism between families is a change to the city, never an optimisation.

Bin Rules — phases 1–3

Scheduled on the Event Wheel, evaluated read‑only, applied atomically in a drawn order. On failure they subscribe to the Bin that stopped them and cost nothing until supply arrives.

Sweep Rules — phase 6

Fire on an interval, sample a derived number of rows, and act where they run. No wheel entry, no subscription, no proposal.

Atomicity, in one paragraph

Check accumulates net deltas per distinct Bin — not term by term. That is not a refinement: term‑by‑term, a Rule naming one Bin on both sides can be refused headroom in a Bin it was about to empty, and nothing else would ever drain it. Then per Bin, affordable = level ÷ |delta| (or headroom ÷ delta), and the count is min(ceiling, every affordable). Checking at n and applying at n are one arithmetic, not a search.

Fallback chains

Out‑degree 1, so a chain is a path. The rule that surprises everybody: a terminal link is never evaluated. Evaluating it would succeed, re‑arm the head at rate, and walk the chain every rate Ticks for the whole shortage — which is the polling defect that subscription exists to remove. Every link must relieve the same Bin the head can fail on (enforced at load), so one subscription covers every rescue path and depth costs no subscriptions.

The Ruleset file

Three shipped files, all under rulesets/. minimal.toml says in its own header, at length, that it models no city and is not the beginning of one. Read that header — it is a design record, not boilerplate.

[[building]]

    { resource = "sundries", capacity = 48 },
    { resource = "repairs",  capacity = 4 },
]
condemn_after = 4

[[rule]]

[[zone_rule]]

Twelve top‑level tables exist: [[resource]], [[building]], [[rule]], [[zone_rule]], [layers], [placement], [roads], [lots], [trips], [jobs], [households], [traffic]. The last two are stated by no shipped file.

Three conventions that recur everywhere
  • The file states a duration; the engine derives the count. revisit_ticks plus interval gives sample = ceil(rows × interval ÷ revisit). Authoring the sample directly is how a mechanism silently stops existing as the city grows — the retired key sample is now refused by name, because a silently‑ignored key is how a designer's tuning stops taking effect with nothing saying so.
  • Absence is a stated city, and the polarity is chosen per table. No [traffic] means roads never slow down; no [households] means nobody drives; no [placement] means the city houses nobody. Only [layers] has a working default, because its default is the prior behaviour.
  • Derived‑from‑the‑Ruleset‑in‑force beats saved for anything that is a pure function of the Rules — Bin capacity, occupancy ceiling, car ownership, the departure window. Freeze it at construction and a hot reload divides the city into before‑and‑after with the cause recoverable from no state.

No decimals anywhere, in any section, including ones this build does not read — a double that exists for microseconds becomes a cross‑machine hash divergence with no diff. Quote them if you need them. And declaration order is content: it assigns ids, and it is the Zone Rule tie‑break.

Adding a Ruleset key, end to end

  1. src/Borough.Core/Rules/Ruleset.cs — add the field, and decide the polarity of absence explicitly and write it in the remarks.
  2. src/Borough.Formats/RulesetLoader.cs — four edits: a case in Enumerate, the default: message listing the sections, a ReadX() returning X.None, and the range refusals. Give each refusal the mechanism sentence, not just the range.
  3. src/Borough.Core/Rules/RulesetShape.cs — re‑run the membership test: anything a live row can point at is structure; anything only read through a row is a number. Get this wrong in one direction and every tuning reload becomes a migration.
  4. If the value is derived‑and‑rebuilt, add the rebuild to World.Adopt.
  5. Tests: there is already one file per table under tests/Borough.Tests/Formats/.
  6. State the number in rulesets/*.toml — which moves the file's content hash and therefore re‑baselines the golden session. See 07.
  7. Record the unratified number in plans/0002 §D with a named ratifier.

Hot reload

A Ruleset is identified by the content hash of its file (CRLF normalised, nothing else — whitespace, key order and comments are content). The log carries the hash, never the Rules, so supplying the wrong file is loud rather than quiet. An unresolvable hash throws: silently ignoring a reload is the named failure mode of the whole feature.

World.Adopt refuses first, then applies. World.Migrate is four separate walks rather than one loop doing four things — step 4 allocates rows step 2 just freed, so interleaving is a different slot assignment and therefore a different State Hash.

The acceptance test for the whole feature — change a production ratio and see the effect in seconds — reads 0.70 s.

06

Movement — the live frontier

This is where the work is right now, and it is the subsystem with the most decisions behind it. Read docs/movement-primer.md first; it exists exactly for this.

The three‑way split

RowOwnsLifetime
Trippurpose, origin, destination, an ordered list of Legs, and a Fateone journey
Legthe plan: one mode‑homogeneous piece, with a cost and now a routeone journey
Travellerthe cursor: which Leg, which hop, sub‑Tick carry, arrival Tickreleased on arrival — a view, never an owner

A car commute is never fewer than three Legs — walk → drive → walk — because Buildings connect to the pedestrian network rather than to the road graph. The two flanking walks are zero‑length until parking exists (milestone 8), and that placeholder is named rather than silent.

TripFate is a closed set of four, with InFlight = 0 so an unwritten row cannot read as an outcome: Completed, NoRouteFound, ExceededCommuteBudget, Stranded.

Routing

  • WalkRouting.Cost — a real Dijkstra, but with three closed‑form answers before any search: absent/dead endpoints, the same‑Segment case, and an exact reachability reject off per‑mode connectivity components. It seeds both origin endpoints and reads both destination endpoints, which is why it is Dijkstra and not A*.
  • WalkScratch — generation‑stamped search state, never cleared. Arrays beside the search, deliberately not a [Table]: never saved, never hashed. One per caller, never shared across threads.
  • RouteCache — four‑way set‑associative, keyed on a node pair, never on an agent. Stores each Segment's handle and its Epoch, so a lookup rejects if the graph moved. This is the first reader the per‑Segment Epoch has ever had. Eviction is MRU, chosen structurally — a commute is a once‑per‑Day cyclic scan, which is LRU's worst case (measured: LRU 2.83% hit rate, MRU 19.54%).
  • TravelTimeMatrix — free‑flow time between every ordered pair of routing partitions. Times only, no routes. Asymmetric: n², never n²/2.

Milestone 5c — in flight, tasks 1–6 of 8 done

Shipped in the working tree right now: the routing partition, the travel‑time matrix, the path source, the route cache, the vehicular Leg, and the volume‑delay function. RouteHopTable.cs is still untracked. Remaining: task 7, a runner mode showing where the traffic is, and task 8, the 100,000‑Tick long run — which is the named ratifier for four hash‑bearing numbers that no shipped Ruleset states.

Space: Tile, Cell, Chunk

  • Tile ≈ 4 m.
  • Cell = 32×32 Tiles ≈ 128 m. A frozen design constant, never tuned, because changing it changes the State Hash. Every conversion is a shift.
  • Chunk = a multiple of the Cell, provisionally 1:1.
  • Map: 512 Cells a side = 16,384 Tiles = 65.5 km.

The graph is Nodes, Segments and a directed Arc adjacency. The mode mask is saved on the Arc and derived on the Segment — one‑way streets are the entire reason. This is where Severance lives: an Arterial's Arcs carry Car and not Foot, so a pedestrian route genuinely does not exist. Nobody deletes it.

The per‑Segment Epoch is monotone and saturates at uint.MaxValue rather than wrapping — a wrapped Epoch makes a stale route compare valid. Laying a Street moves no standing Segment's Epoch: an addition cannot make an existing route wrong, only suboptimal.

The suite tests the documentation

Five checks in tests/Borough.Tests/Corpus/: every ADR is cited by something outside docs/adr/; every relative markdown link resolves (2,292 of them); every ADR has a row in the coverage map; certain dangerous figures are never quoted without their disqualifying caveat; and markdown tables are not split into fragments that will not render. If you edit a document and the build goes red, this is why.

The golden baselines

The point, stated in the README's first line

Not that the State Hash never moves — that it never moves without somebody saying so. Every other determinism test is a closed loop: it runs a thing twice and checks the two runs agree, which stays true however far the simulation has drifted from what it used to compute. These are the only numbers recorded on a previous day.

Three committed artefacts, plus two that are part of the baseline and live elsewhere:

  • Golden/session.borough — the Input Log: seed, 4,000 Citizens, 21 commands, a reload at Tick 1,024.
  • Golden/session-trace.txt — 32 hash samples of that 2,048‑Tick session.
  • Golden/world-hash.txt — one hash over a hand‑built city that reaches free‑list state a session cannot.
  • rulesets/minimal.toml and minimal-tuned.toml — named by content hash, so editing either moves every sample above.

Re-baselining

  1. Establish which kind of change it is. A change is an optimisation if the State Hash is unchanged and a design change otherwise, however it was motivated. If you believed you were writing an optimisation, this test has just told you that you were not. Stop and find out what moved.
  2. Regenerate: 
    dotnet run --project src/Borough.Headless -- \
  --log tests/Borough.Tests/Golden/session.borough \
  --ruleset rulesets/minimal.toml \
  --ruleset rulesets/minimal-tuned.toml \
  --ticks 2048 --hash-every 64 \
  --out tests/Borough.Tests/Golden/session-trace.txt
    Both --ruleset flags are mandatory, because the session reloads. For world-hash.txt, copy it out of the failure message — the test prints the file in full.
  3. If the fold itself changed — composition order, Randomness.Mix, what a column contributes — bump the version byte in World.HashSeed. A behaviour change moves the baselines and leaves the seed alone.
  4. Say why in the commit message, naming the document or ADR that authorises it. A re‑baseline whose message is "update golden hashes" is one nobody can audit later.
  5. Never in the same commit as an unrelated change. The diff is the record.

There is deliberately no --update-baselines switch and no environment variable. A baseline that can rewrite itself is one CI misconfiguration away from approving every change it sees.

The gotcha, documented twice in that README

When a Ruleset gains a table, four literals in two files must move before the trace can be regenerated at all: GoldenFixtures.RulesetHash, GoldenFixtures.TunedRulesetHash, and the ruleset and reload lines inside session.borough. Regenerating against a log that still names the old Ruleset produces a green run of the wrong session.

The failure a baseline is structurally blind to

A baseline records what a run did, so a change that narrows what the run reaches is invisible in it by construction — every hash moves, every test passes, and half a mechanism goes uncovered. This has now happened twice, so it is a test rather than a paragraph: GoldenSessionCoverageTests asserts what the session reaches. If you move a command in that session, that file is what tells you the move cost coverage.

How the corpus works

~33,000 lines of prose against ~36,000 lines of simulation. That ratio is known, is on the board as a standing concern, and is why the rule is: an argument session runs when something concrete is blocked on it, never because it is available.

ADRs

99 of them, numbered to 0099 (0028 is reserved and unwritten). The filename is the claim, stated as a sentence — 0075-a-leg-is-a-plan-and-a-traveller-is-a-cursor.md. Structure: title as a claim, the decision in bold up front, ## Why, ## Consequences, ## What would trigger revisiting. That last section is not optional — a decision with no revisit trigger is a decision nobody can reopen honestly. ADRs are never deleted or silently amended; a wrong one gets a correction block, so the reasoning that was wrong stays readable.

Four rules of inference, and one of quotation

These are the load‑bearing meta‑rules. They will feel like overhead until the first time one saves you a week.

RuleGovernsWhat it says
adr/0043claimsA claim a measurement could settle must not be settled by argument. Type it first: can you name the number that would refute this, and the machine that would produce it? Six claims here have been measured false, two of them sitting in documents marked fully argued.
adr/0052numbersA hash‑bearing number is chosen with a named ratifier or not at all. A category is not a name — "a future spike" satisfies the letter and defeats the point.
adr/0070absencesAn unbuilt mechanism is not a design constraint. Classify it: unbuilt, undesigned, or refused — and only refused is evidence. Most of this project does not exist, so "the sim does not do X" almost always means nobody built X.
adr/0093the buildA description of the build is where to look, and never what you found. Where such a sentence is wrong it is wrong about the trigger. The writing half is what compounds: name a symbol, never a time. "At world creation" cannot be checked without already knowing the answer; "when SyntheticCity runs" is one grep.
0012 Cause 5quotationA caveat attached to a number does not travel with it. Quote the sentence, never the digits. Carry the bill, not the percentage — a share of a budget is a measurement over a product decision, so state the milliseconds and let the share follow.

Vocabulary discipline

Domain terms are capitalised in prose. If a concept needs a name that is not in CONTEXT.md, add it there first. The file ends with Terms we deliberately do not use, and several of them name failure modes the design has already rejected — Agent (say Citizen, Traveller or Vehicle), Cohort (there is no group‑level Citizen representation anywhere), Demand (there is no RCI meter; the Unplaced Pool is the demand signal), Region, hour and minute (there is no clock face).

Prose is British — modelled, behaviour, optimise. The register is dense and argumentative. This governs documents only; chat and commit messages are plain English.

The five things not to reach for

  • An ECS. Rejected explicitly: the population is homogeneous.
  • A demand scalar. There is no RCI meter.
  • Collapsing Citizens into groups. No Cohorts, ever.
  • Fidelity that depends on the camera. Fidelity is a property of place, driven by Stress. The renderer cannot influence the simulation.
  • A collection with no sink. Nothing grows with elapsed time.

Operational traps

  • Do not delete spikes/S2.Routing/. It is 29,719 lines awaiting deletion and has been held twice for unrelated reasons. The first gate is discharged; the second (another session is doing live research inside it) is not. Reading the first clearance as the second's is exactly how a row gets struck wrongly.
  • Turn off the Decide guard for long runs only. --no-decide-guard. It is O(world) twice a Tick.
  • Do not share the machine with a benchmark. A dotnet test run at ~1018% CPU has been recorded corrupting a parallel‑scaling measurement in another session.
  • Every diagnostic needs a test that watches it fire. The analyser harness asserts the probe compiles clean first — otherwise a typo makes the positive test fail for the wrong reason and the negative one pass for no reason at all.
  • Rebuilding derived state is a real obligation. A derived structure caching a Ruleset value reads as absent rather than stale before its first rebuild — and absent is the state every guard is written against.

A first contribution, in order of increasing blast radius

  1. Read PROCESS.md, then CONTEXT.md's heading list, then docs/movement-primer.md. Ninety minutes. You will stop mis‑parsing every other document.
  2. Run all seven runner modes. --zones, --roads, --commute and --layer each print a picture. This is faster than reading about them.
  3. Break something on purpose. Write a double in Core and watch BOR0201 fire; change one number in rulesets/minimal.toml and watch the golden baseline fail with a diff. Both take a minute and teach you more than any document.
  4. Pick up 5c task 7 — the traffic runner mode. It is scoped in plans/0026, it is an eighth mode alongside seven existing examples to copy, it touches no hash‑bearing state, and the milestone is blocked on it. That is about as good as a first issue gets here.
The habit that matters most

When you find that a document is wrong, route the finding to the code or to a named document with an owner, on the day, and before working around it. The order is the rule — the filing survives, and doing the workaround first is how the filing stops feeling necessary. A defect goes to the code or plans/0003; a cost to 0013; a question to 0002; a document now wrong to 0012. There is no fifth class.
